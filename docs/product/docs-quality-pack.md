# The `docs-quality` pack (BetterDoc)

> Status: shipped as the first first-party pack (#166). Content lives at
> `packs/docs-quality/aih-betterdoc/`, and curation is committed in
> `aih-packs.json`. This self-hosting checkout intentionally has no product
> approval lock, vet report, or promoted runtime copy (#508). A different target
> repository can seed the bundled bytes, then create its own vet, approval, and
> install state under that repository's policy.

`docs-quality` is aih's own documentation pack. Its single skill, **BetterDoc**, is a
claim-first, evidence-grounded documentation skill: it edits, reviews, and creates
source-grounded technical and product docs and runs a bounded anti-slop lint that never
overrides source truth. It is aih's first-party replacement for the external
`github:hardikpandya/stop-slop` reference in earlier design docs, and it doubles as the house
doc style for release notes.

The skill source under `packs/` is the canonical distribution source. This
repository also commits a CLI-neutral copy under `ai-coding/curated-skills/` for
its own agents; that copy is manually adopted and AIH does not project or
refresh it. `aih pack install` promotes a separate generated copy into a target
context directory's `skills/` root. Generated promotion output is not committed,
The repository test byte-pins the four reference files shared by the source and
curated copies; the curated `SKILL.md` and source-only files are not synchronized
by AIH, so those homes can still drift and must be reconciled through ordinary
review.

## Distribution: a first-party bundled local source

aih ships the BetterDoc bytes in-repo and declares them as a **local source**
(`commit: "local"`) in the pack manifest. That declaration locates bundled
content; it is not approval authority. This checkout's trust anchor for shipped
bytes is human review plus Git provenance, and the self-hosting rule forbids
running aih's product vet/approve/install behavior against this repository.

A downstream repository receives copied first-party bytes through `pack
scaffold`, then owns its own approval decision. Its lock entry and vet report
must be freshly produced under its policy; neither the bundled manifest nor the
committed skill card pre-approves the downstream copy. `pack install` still runs
the target repository's trust checks before promoting content.

### First-party trust tier (verdict grading for first-party sources)

`aih skill vet` grades a source GREEN/YELLOW/RED/UNKNOWN. Previously, an **unavailable** deep
detector (SkillSpector via Docker, or the Cisco skill-scanner via `uvx`) forced **UNKNOWN** for
*any* source, and `skill approve` refuses UNKNOWN. That is correct for a remote fetch — without
the deep scan you cannot vouch for downloaded code — but it made a first-party skill impossible to
approve on a machine or CI without Docker.

The verdict engine (`src/skill/verdict.ts`) scopes that rule so it applies to
every source **except a first-party one**. In the different repository performing
the vet, a **first-party** source is a local path resolved **under that target's
root** (for example, bytes it scaffolded into `packs/`). It is graded on
aih-native coverage, so a merely *unavailable* deep detector no longer forces
UNKNOWN. A local path outside that target is not first-party and stays strictly
graded (still UNKNOWN without the detectors). The exemption is narrow and
detector-only:

- a native malicious-code finding is still **RED**,
- a shape trigger (install scripts / MCP config / full-codebase analysis) is still **YELLOW**,
- a missing license is still **UNKNOWN**,
- when Docker/`uvx` **are** available, the deep detectors still run on first-party sources and still
  escalate on their findings.

Residual risk: an in-target path can be graded on native coverage if a deep
scanner is unavailable, so a scanner-equipped box can still add useful coverage
before that target approves it. The boundary is deliberately narrow — only
repo-relative, human-reviewed, Git-tracked content qualifies; anything fetched
or outside the target is unchanged — but it is a real security-posture choice.
This page makes no current approval or detector-pass claim for the ai-harness
self-hosting checkout because its lock and report are intentionally absent.

> Owner decisions (F3, resolved): the first-party approval model is the **native tier scoped to
> repo-relative sources**, with a first-party marker on the approval for auditability.
> Packaging has been revisited now that `aih pack scaffold` reads bundled pack assets:

## Install and verify

```console
# Run only inside a different target repository, never the ai-harness checkout.
cd /path/to/different-target-repository

# Seed the bundled bytes if the pack is not already committed there.
aih pack scaffold --pack docs-quality --apply

# Create that repository's evidence and approval record before install.
aih skill vet packs/docs-quality/aih-betterdoc --apply
aih skill approve packs/docs-quality/aih-betterdoc --owner <team> --pack docs-quality --apply

# Preview (read-only) — resolves the local source and shows what install would promote.
aih pack plan --pack docs-quality

# Install — trust-scan then promote aih-betterdoc into <contextDir>/skills/.
aih pack install --pack docs-quality --apply

# Confirm governance state.
aih pack status --pack docs-quality      # ready · 1 approved · 1 installed
aih skill inventory                      # aih-betterdoc [approved] (… · docs-quality · promoted)
aih pack validate                        # coded findings, non-zero exit when blocked
```

At the default (non-enterprise) posture `pack install` promotes even when the deep detectors are
absent — install trusts that repository's recorded approval and a non-failing trust scan. At
enterprise posture with a required detector, an unavailable detector fails the scan and blocks
install by design.

## Updating BetterDoc

In the ai-harness source repository, update
`packs/docs-quality/aih-betterdoc/`, review the public diff, and run the
repository-owned tests and documentation gates. Do not run AIH product behavior
against this checkout and do not recreate a root approval lock here.

After a package containing the reviewed bytes is available, a different target
repository may scaffold it and run its own vet → approve → install lifecycle.
That target records its own evidence, owner, decision, and promoted copy. The
`aih-packs.json` ref remains `commit: "local"`; it locates scaffolded first-party
content and does not need a remote pin.

## Native documentation checks

BetterDoc's prose vocabulary also feeds the shipped native `aih docs-lint`
surface. Prose findings remain advisory; the separate claim ledger fails closed
when a public assurance claim lacks its control-matrix/test proof. The source
vocabulary remains
`packs/docs-quality/aih-betterdoc/references/slop-lint.md`; native enforcement does
not turn the BetterDoc pack into approval authority for this checkout.
